# itonami-selective-regression-pins

Choose one model gap, baseline revision, exact runner, input and expected observable. Read the actual measurement output before adopting a README value. Missing dependencies or zero loaded tests leave the run unmeasured; a compatibility mirror is a different execution route and must be labeled.

On an isolated caller-authorized checkout, measure baseline and candidate using the same effective runner and dependency identities. Preserve units, finite-value checks, tolerance and output keys. Do not copy a compacted summary's numbers into a new measurement receipt.

When a regression pin is justified, show that it fails for the targeted broken behavior. Where two independent break modes are relevant, test each and verify that unrelated control pins still behave as expected. Preserve unchanged model invariants rather than rewriting acceptance criteria to pass.

Report the reproducible observation, break evidence and unresolved runtime route. A proposed pin is source/model evidence, not human, native hardware or production qualification. Keep owner merge/adoption policy separate from drafting the improvement.

Pinned derivation inputs are in itonami.json and catalogs/sources.json; owner runtimes and profiles are referenced, not imported.

# ADR 0006 Compat monorepo

Status: accepted, 2026-10-23 (JUN-347).

## Decision

The clean-room compat actors that lived one-per-repository in kotoba-lang (`com-*` repositories whose `manifest.json` has `kind: compat`, for example `com-circleci`) are consolidated under `compat/<slug>/` in this repository. 1027 repositories were present at import.

This amends ADR 0001 for this one family: ADR 0001 keeps source in the owning repository, but compat actors are small, uniform and have no other owner, so the owning repository is now this one. Profiles, agents, skills, MCP definitions and workflows are unchanged.

## Shape

- `compat/<slug>/` holds the repository tree as it stood at the pinned commit, minus `.github/` (no CI definitions are carried) and minus credential or state files, which the importer refuses.
- Git history is preserved: each source history was rewritten under `compat/<slug>/` and merged, so `git log -- compat/<slug>` and blame continue to work. Commit hashes change; the original commit is pinned in `catalogs/compat-sources.json`.
- `catalogs/compat-sources.json` records, per slug, the origin repository, the original commit and any excluded paths.
- `compat/index.json` is generated by `scripts/build_compat_index.py` (`--check` in validation) with a folder checksum per entry.
- compat is not a Hermes entry type and is not in the Hermes `index.json`; ADR 0001's four manifest types and ADR 0004's auxiliary-catalog rule are untouched.

## Non-claims

Registration grants no authority and activates nothing. `wasmCid` and `verified` values are copied from each manifest and were not re-verified by the import; no entry is claimed to run, to match its vendor API, or to be deployed. The `tier` is the source's own claim.

## Origin repositories

The importer never modifies a source checkout. What happens to the kotoba-lang repositories after the import is recorded in JUN-347, not here.

## Relation to ADR 0005 (api entries)

ADR 0005 describes each compat actor's API shape as an `api` entry in `apis/<id>/`, self-pinned to the origin kotoba-lang repository and commit. This ADR holds the actor's code and history. They are different identities and neither replaces the other.

Consequence and decision: because the origin repositories are retired (archived, then deleted), the 1027 compat `apis/<id>` pins are repointed here. `pin.repository` is this registry, `pin.commit` is the registry commit that introduced `compat/` (`registryCommit` in `catalogs/compat-sources.json`), `pin.path` is `compat/<id>`, and `source` carries the same path. File sha256 values are unchanged, which shows the trees are identical. `pin.origin` keeps the original repository and commit, and `version` still derives from the origin commit. The classification row keeps the origin identity and gains `retiredTo`. The `client` entry and the unclassified rows are untouched and still pin kotoba-lang.
